# Probabilistic joint state–force estimation in a beam–moving-mass system from single-point vibration measurements

Reference implementation for the paper of the same title (E. Ghorbani, J. Hackl, E. Hernandez; *Journal of Sound and Vibration*, manuscript JSV-D-26-01502, revised October 2026).

An adaptive unscented Kalman filter (AUKF) jointly estimates the modal states of an Euler–Bernoulli beam, the mass and speed of an object crossing it, and the beam–object interaction force from a single mid-span measurement (displacement or acceleration). The moving object is modelled as a travelling mass whose inertial, centrifugal and Coriolis forces couple to the beam; mass and speed are appended to the state vector as unknown constants, and the measurement-noise covariance is adapted online from the innovations.

All code is MATLAB (tested with R2023b; `verify_iso8608.m` needs the Signal Processing Toolbox). Every script is run from inside its own folder.

### Cases 1 and 2 (Section 5)

`BMM_SS.m` is the beam–moving-mass state-space model used to synthesise the data (RK4 integration in `ode4.m`, mode shapes in `mode_shapesPP.m`), `BMM_UKF.m` the same model with mass and speed appended to the state, `TF.m` one RK4 step of it, `sigmapoint.m` the sigma-point set, and `run_UKF_displacement.m` / `run_UKF_acceleration.m` the adaptive UKF loop. The main scripts generate the data, add the time-varying measurement noise of the paper, run the filter and write the figures. `Sim_hist_noise.m` draws the noise histories shown in Section 5.1.

### Case 3 (Sections 6 and 7)

The beam–moving-mass model is extended to a moving oscillator (sprung mass on a suspension over an unsprung wheel mass) crossing a damped beam on a stochastic deck profile generated from the ISO 8608 spectrum. The filter keeps the rigid-mass, undamped, smooth-deck model of Section 2, so the extra physics acts as model-form error. The same extended code, with the model error switched off, runs the 147-case generality study of Section 7 with the four-filter speed bank. See `case_3_roughness/readme.txt` for the file list and the exact run order.

## Data

The `.mat` result files and run logs are not in the repository (several hundred megabytes); every result is regenerated by the scripts listed above with fixed random seeds. Contact ghorbani@princeton.edu if you need the stored results.
